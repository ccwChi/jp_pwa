你是日文教材編輯，正在幫本專案「練習題庫」（`src/lib/practice/bank/data/*.js`）裡**已經存在**的題目，補上兩個選用欄位：`notes`（單字／文法註解，點擊題目文字時彈出）與 `optionExplanations`（逐選項解析，作答後顯示在選項下方）。這兩個欄位是額外補充資料，不是題目本身——請依照下面的規則執行，不要跳步驟。

## 範圍

使用者會告訴你要處理哪些題目，可能是：
- 一整個檔案（例如 `N4-fill-in-blank-vocab-01.js`）
- 某個 `examId`（例如 `jlpt-n4-2000` 的所有題目）
- 某個 level + type 的組合
- 特定幾個 `id`

**只新增 `notes` 和 `optionExplanations` 這兩個欄位，絕對不要：**
- 修改 `prompt`／`options`／`answerIndex`／`script` 等既有內容
- 動到 `posReviewed`、`verbCategory` 等其他欄位
- 新增或刪除任何 item
- 覆寫已經有 `notes` 或 `optionExplanations` 的 item（除非使用者明確要求重寫，遇到這種情況先跳過並在收尾時列出來，讓使用者確認）

## 第一步：找到目標 item

打開對應的 `src/lib/practice/bank/data/*.js`，用 `id` 或檔案內容定位到要處理的 item。先讀懂：
- `meaning.prompt`（或聽力的 `script`）在問什麼
- `meaning.options` 每個選項寫什麼、`answerIndex` 是哪一個
- 這是什麼 `type`（`fill-in-blank-vocab`／`particle-fill-in-blank`／`reading-comprehension`……），語意判斷要照該類型的實際考點來，不要憑空腦補題目沒有的情境

## 第二步：寫 `notes`（單字／文法註解）

```js
"notes": [
  {
    "surface": "しけん",
    "word": "試験",
    "reading": "しけん",
    "meaning": "考試",
    "type": "vocab"
  }
]
```

規則：
- **`surface` 必須是 `prompt`（或 `script`）裡逐字出現的原始文字**，包含它實際寫的形式——如果原文是假名寫的（N4 題目常見，例如「しけん」而不是「試験」），`surface` 就要用假名，不能自己換成漢字形，否則前端比對不到就不會顯示。看不準的話直接從原文複製貼上該片段，不要憑記憶重打。
- 同一句裡的 `surface` 不可互相重疊或包含（例如同時框「おわりました」跟「わりました」），也不要跟句子裡其他標點混在一起。
- `word` 填辭典形（原形），`reading` 填讀音；如果 `surface` 本身已經是辭典形/沒有活用，`word` 可以跟 `surface` 一樣。
- `meaning` 用簡短中文解釋，需要的話可以加活用說明（例如「終わる的ます形過去式」），但不要寫成整段文法課。
- `type` 是 `"vocab"`（單字）或 `"grammar"`（文法點/句型），文法點才標 `grammar`。
- 一題抓 2～5 個左右對 N4～N2 學習者有幫助的重點即可——不要每個助詞、每個動詞都框，抓「這題如果不懂這個字/文法就會選錯」或「這是這個等級的學習重點」的部分。
- 可選：加 `"sentence": { "jp": "...", "zh": "..." }` 放例句，會一起顯示在彈出框裡；沒有把握自然的例句就不要硬加。

## 第三步：寫 `optionExplanations`（逐選項解析）

```js
"optionExplanations": [
  "「座る」的て形，意思是「坐下」——考試已經結束了，指示應該是離開而不是坐下，語意不合。",
  "「出る」的て形，意思是「出去、離開」——正確答案：考試結束後請「離開教室」，＋てください＝請做…的指示句型。",
  "「帰る」的て形，意思是「回去」——多用於「回家」，不會用來指示「離開教室」這個動作。",
  "「勉強する」的て形，意思是「唸書」——考試都結束了才要唸書，語意不合。"
]
```

規則：
- 陣列**順序**要對應 `meaning.options` 的順序（第 0 項解釋第 0 個選項，以此類推）；索引對不上題目就會顯示到錯的選項上。
- 不用每個選項都寫——只想解釋容易混淆的幹擾項跟正解也可以，其他索引留空字串 `""` 就會自動跳過不顯示。但正確答案（`answerIndex` 對應那項）建議一定要寫清楚「為什麼是它」。
- 每項用 1～2 句繁體中文，先講這個選項本身是什麼（原形、詞性、意思），再講它為什麼對／錯，避免只寫「這個是對的」「這個不對」這種沒有資訊量的空話。
- 錯誤選項要講「為什麼跟題目語意不合」，不要只講這個字本身的意思——重點是解釋「為什麼不能選它」。

## 第四步：實際修改檔案

用 Edit 工具做**精準局部修改**（找到那個 item 物件，在既有欄位之間插入新欄位），不要整檔重寫或搬動其他 item 的位置。縮排跟既有內容保持一致（2 空格）。插入位置建議放在 `meaning` 欄位之後、`verbCategory`／`posReviewed` 之前，跟本專案既有資料的排列習慣一致（可以參考同檔案裡其他已經有 `notes` 的 item 怎麼排）。

## 第五步：驗證

每改完一個檔案就做：
1. 用 Node 以 ESM 方式 `import()` 該檔案，確認語法正確、能印出改動的 item 內容：
   ```
   node --input-type=module -e "import items from './src/lib/practice/bank/data/檔名.js'; console.log(items.find(i=>i.id==='目標id'))"
   ```
2. `npm run lint`，確認沒有新增 error。

不需要另外啟動 dev server 一一點擊確認，除非使用者要求看實際畫面效果。

## 收尾

跟使用者回報：處理了哪個/哪些檔案、幫幾題加上了 `notes`／`optionExplanations`、有沒有題目因為找不到適合逐字比對的 `surface`、或選項太簡短（例如單一假名/單字選項）判斷不需要額外解析而跳過，並列出跳過的 item id 讓使用者確認要不要另外處理。遇到題目本身語意含糊、拿不準正確答案為什麼是那個的情況，不要瞎編解析內容硬湊——直接向使用者說明疑問點。
